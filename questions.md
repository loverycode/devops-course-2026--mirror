Напрямую в main обычно не коммитят, чтобы непроверенный код не попал в основную ветку. Изменения проходят через отдельную ветку, Pull Request, Code Review и тесты.
GitHub Flow: создать ветку от main → внести изменения → сделать коммиты → отправить ветку на GitHub → создать Pull Request → пройти Code Review и CI → объединить с main → удалить ветку.
Pull Request — это процесс обсуждения и проверки изменений, а merge — непосредственно операция объединения веток.
Code Review — проверка изменений другими разработчиками. Он нужен для поиска ошибок, повышения качества кода и обмена знаниями.
Git — распределённая система, где есть локальный репозиторий с историей. SVN — централизованная система, где основная история хранится на сервере.
feat: означает, что коммит добавляет новую функциональность.
Первоначально локальную ветку отправляют командой:
git push -u origin название-ветки
DevOps-инженеру нужен Git в терминале, потому что инфраструктура, CI/CD и конфигурации работают преимущественно в серверной и автоматизированной среде, где GUI может отсутствовать.
